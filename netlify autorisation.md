# Промт для Claude Code: сайт психолога [Ім'я Прізвище]

Скопіюй усе нижче як стартовий промт (або поклади цей файл як `CLAUDE.md` у корінь проєкту) і скажи Claude Code в VS Code: **"Створи сайт за цим технічним завданням"**.

---

## 1. Контекст проєкту

Створи статичний сайт-візитку (HTML/CSS/JS, без WordPress і без фреймворків) для приватного психолога **[Ім'я Прізвище]**.

- Практика: очні консультації в **Черкасах** + онлайн-консультації по всій Україні та для українців за кордоном (Європа).
- Мова сайту: **тільки українська**.
- Тон: теплий, дбайливий, без клінічного/медичного жаргону, без надмірного маркетингового тиску. Довіра важливіша за продаж.
- Це MVP-версія: текстовий контент на сторінках послуг і в блозі поки що **лорем іпсум** — реальні статті я напишу пізніше. Але структура, заголовки, мета-теги і SEO-розмітка мають бути фінальні, готові до заповнення.

Дизайн і структура спираються на аналіз конкурентів і ключових слів, зроблений раніше (сайти: kolosova.org, oksanamatvisiv.com, mysense.ua, newleaf.ua, goodpsy.in.ua та інші) — орієнтуйся на їхні патерни подачі (відкрита ціна, FAQ про формат сесій, розділ "з чим я працюю", соцдоказ), але не копіюй дизайн один в один — потрібен власний, впізнаваний вигляд під бренд нижче.

## 7. SEO — обов'язкові налаштування

**Ключові слова** (взяти з попереднього аналізу ніші — розподілити по сторінках):

- Головна: `психолог черкаси`, `психотерапевт черкаси`
- `/onlayn-konsultatsii/`: `психолог онлайн україна`, `консультація психолога онлайн`
- `/dlya-ukraintsiv-za-kordonom/`: `психолог для українців за кордоном`, `психолог онлайн для українців в [країна]`
- Сторінки послуг: по одній проблемній фразі на сторінку — `психолог від панічних атак`, `психолог вигорання`, `психолог після втрати близької людини`, `психолог низька самооцінка`, `адаптація за кордоном психолог` тощо (відповідно до теми сторінки)

**На кожній сторінці:**
- Унікальний `<title>` (50–60 симв.) за шаблоном: `[H1-фраза] — [Ім'я Прізвище], психолог у Черкасах`
- Унікальний `<meta name="description">` (140–160 симв.), з ключовою фразою і CTA
- Один `<h1>` на сторінку, логічна ієрархія `h2`/`h3` без пропусків рівнів
- `<link rel="canonical">` на кожній сторінці
- Open Graph теги (`og:title`, `og:description`, `og:image`, `og:locale` = `uk_UA`) + Twitter Card
- `alt` для всіх зображень (описовий, з ключовим словом де доречно, без переспаму)
- Семантичний HTML5: `<header>`, `<nav>`, `<main>`, `<article>`, `<aside>`, `<footer>`

**JSON-LD структуровані дані:**
- `Person` + `ProfessionalService`/`PsychologicalTherapy` на головній і сторінці "Про мене" — ім'я, спеціалізація, місто (Черкаси), посилання на соцмережі
- `FAQPage` на кожній сторінці послуги й статті блогу, де є FAQ-блок
- `BreadcrumbList` на всіх внутрішніх сторінках
- `BlogPosting` на сторінках блогу

**Технічний SEO:**
- Згенерувати `sitemap.xml` з усіма сторінками
- `robots.txt` з посиланням на sitemap
- Локальне SEO: вбудована Google Карта з локацією кабінету в Черкасах на `/kontakty/`, NAP (ім'я/адреса/телефон) однаковий у футері й на сторінці контактів
- Оптимізація зображень (WebP + fallback, `loading="lazy"` для всього нижче першого екрана)
- Мінімальний і акуратний CSS/JS без зайвих залежностей — швидкість завантаження критична для SEO

Обов'язкові розділи (текст — типовий шаблон, юридично базовий, не є заміною консультації юриста):
- Які дані збираються (ім'я, контакти, дані форми запису)

- Контакт для звернень щодо даних

## 11. Decap CMS — адмінка для самостійного редагування

Мета: щоб я могла правити тексти, робити перелінковку і публікувати статті блогу через просту веб-форму на `/admin`, без відкриття коду.

**Важливий технічний нюанс.** Чистий "розсипаний" HTML (розділ 4) погано поєднується з CMS — редагувати markdown-контент і рендерити його назад у ту саму розмітку з усіма мета-тегами й JSON-LD напряму складно й крихко. Тому для цього блоку познач у проєкті невеликий генератор статичних сайтів **Eleventy (11ty)**: він не ламає жодну з вимог вище (вихід — усе одно чистий статичний HTML/CSS/JS, без фреймворків на фронті), але дозволяє тримати HTML-шаблони окремо від контенту. Усі шаблони з розділів 5–9 стають Nunjucks-шаблонами (`.njk`), а сам контент (тексти, FAQ, ціни) — окремими markdown/YAML-файлами, які і редагує CMS. Собери проєкт так з нуля, а не переробляй потім.

**Структура для CMS:**

```
/admin/
  index.html        ← підключає Decap CMS (CDN-скрипт)
  config.yml         ← опис колекцій нижче
/content/
  pages/
    home.md
    pro-mene.md
    tsiny.md
    onlayn-konsultatsii.md
    dlya-ukraintsiv-za-kordonom.md
    pryvasi-polisy.md
  services/
    tryvoga-panichni-ataky.md
    emotsiyne-vysnazhennya-stres.md
    ... (8 файлів — по одному на послугу)
  posts/
    приклад-статті.md
/public/img/uploads/   ← медіа-бібліотека CMS (фото до статей)
```

```yaml
    folder: "content/services"
    create: false               # 8 сторінок фіксовані, нові не потрібні
    slug: "{{slug}}"
    fields:
      - { label: "H1 (назва напрямку)", name: "title", widget: "string" }
      - { label: "Лід-абзац", name: "lede", widget: "text" }
      - { label: "Meta title", name: "seo_title", widget: "string" }
      - { label: "Meta description", name: "seo_description", widget: "text" }
      - { label: "Коли варто звернутись", name: "symptoms", widget: "markdown" }
      - { label: "Як проходить робота", name: "approach", widget: "markdown" }
      - { label: "Що зміниться", name: "results", widget: "markdown" }
      - label: "FAQ"
        name: "faq"
        widget: "list"
        fields:
          - { label: "Питання", name: "question", widget: "string" }

      - label: "Пов'язані сторінки (перелінковка)"

          - { label: "Питання", name: "question", widget: "string" }

      - label: "Пов'язані послуги (перелінковка)"
        name: "related_services"
        widget: "relation"
        collection: "services"
        search_fields: ["title"]
        value_field: "{{slug}}"
        display_fields: ["title"]
        multiple: true
        required: false

  - name: "pages"
    label: "Сторінки"
    files:
      - { label: "Головна", name: "home", file: "content/pages/home.md", fields: [ { label: "Блок 'Я допомагаю при'", name: "help_with", widget: "list" }, { label: "Текст під блоком", name: "quote", widget: "string" } ] }
      - { label: "Про мене", name: "pro-mene", file: "content/pages/pro-mene.md", fields: [ { label: "Текст", name: "body", widget: "markdown" } ] }
      - { label: "Ціни", name: "tsiny", file: "content/pages/tsiny.md", fields: [ { label: "Текст", name: "body", widget: "markdown" } ] }
      - { label: "Політика конфіденційності", name: "pryvasi-polisy", file: "content/pages/pryvasi-polisy.md", fields: [ { label: "Текст", name: "body", widget: "markdown" } ] }
```

Поле `relation`/`related` у "services" і "posts" — це і є перелінковка через CMS: обираєш зі списку, до яких сторінок посилатись, і шаблон сам вставляє блок "Читайте також" з правильними `<a href>`. Це набагато безпечніше за ручне редагування посилань у коді.

**Авторизація й деплой (зроби в такому порядку):**

1. Задеплой сайт на **Netlify** (безкоштовний план вистачає) — підключи git-репозиторій напряму з GitHub.
2. У Netlify: `Site settings → Identity` → Enable Identity, тоді `Identity → Services → Git Gateway` → Enable. Це дає логін/пароль для `/admin` без окремого сервера.
3. Запроси себе як користувача через `Identity → Invite users` — прийде лист із посиланням на встановлення пароля.
4. Після цього `тво-сайт.netlify.app/admin` (а пізніше — `твійдомен.com/admin`) відкриває форму логіну і саму CMS-адмінку.

Після переходу на Eleventy онови також розділи 5–9 вище: усі `lorem ipsum`-плейсхолдери в шаблонах заміни на змінні з front-matter (`{{ title }}`, `{{ symptoms }}` тощо), а не залишай текст захардкодженим у HTML.
